# Sample outputs

Ready-to-read examples produced by this agent from the two sample project plans
(`project_plans/`), so you can see the deliverables without running anything.

| File | What it is | Deliverable |
|---|---|---|
| `Weekly_Report_UniSan.md` / `.json` | Weekly RAG health report for the UniSan project (human-readable + structured) | Phase 2 — weekly output |
| `Weekly_Report_Titan.md` / `.json` | Weekly RAG health report for the Titan project | Phase 2 — weekly output |
| `Client_Deck_UniSan.pptx` | Client-safe status deck for UniSan (progress, timeline, next steps) | Phase 3 — client deck |
| `Client_Deck_Titan.pptx` | Client-safe status deck for Titan | Phase 3 — client deck |
| `INTERNAL_ONLY_Portfolio_Deck.pptx` | **The monthly executive presentation** — cross-project trends, emerging risks, and recommendations for leadership | Phase 3 — monthly synthesis |

## About the narrative text in these samples

The **RAG status, all signals, the timeline, the cross-project patterns, and the
numbers** in these files are fully computed and real.

The **prose** (the weekly "why" paragraph and the deck's executive framing) was
written by the **deterministic fallback templates**, because these samples were
generated **without an API key**. That is by design — the tool always produces
valid output even with no key.

To regenerate these with the **live LLM** (Google Gemini) and to see the
**agentic Data-Integrity investigation trace** (which only appears when the
model runs):

```bash
cp ../.env.example ../.env      # then paste a free key from https://aistudio.google.com/apikey
python ../run_weekly_all.py --as-of 2026-07-10          # live weekly reports
python ../generate_monthly_report.py --as-of 2026-07-10 # live decks
```

With a key set, the "Narrative generated by" line changes from
`fallback-template` to `gemini-api (gemini-2.5-flash)`, and any data-integrity
contradiction gains an **Investigation trace** section showing the tools the
model called.

> Note: `.pptx` files here are byte-for-byte copies of what
> `generate_monthly_report.py` writes to `reports/decks/`; they are duplicated
> into this folder only so all deliverables sit in one place.
